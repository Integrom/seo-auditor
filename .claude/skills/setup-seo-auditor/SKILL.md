# Развёртывание «SEO Аудитора»

Помоги человеку поднять приложение и убедиться, что оно работает.

Главный принцип: **не угадывай состояние окружения — запусти диагностику и действуй
по её выводу.** Два инструмента отвечают почти на все вопросы:

```bash
php bin/install.php     # установка: конфигурация, база, каталоги
php bin/check_env.php   # диагностика: 20+ проверок, код возврата 1 при ошибках
```

## Быстрая установка

Требуется PHP ≥ 8.2 (для тестов 8.3+) с расширениями `pdo_mysql`, `curl`, `mbstring`,
`dom`, `json`, `gd`, а также MySQL/MariaDB и Composer. Проверять вручную не нужно —
установщик проверит сам и скажет, чего не хватает.

```bash
git clone https://github.com/Integrom/seo-auditor.git
cd seo-auditor
composer install
php bin/install.php
```

Установщик спросит адрес сайта, часовой пояс и доступ к базе, затем создаст `.env`,
каталоги `reports/` и `logs/`, применит схему и прогонит диагностику.

Автоматический режим без вопросов — для скриптов и CI:

```bash
php bin/install.php --no-interaction \
  --url=http://localhost:8000 \
  --db-name=seo_auditor --db-user=seo_user --db-pass=секрет
```

Если база ещё не создана, добавь доступ администратора MySQL:
`--db-root-user=root --db-root-pass=...`. Установщик сначала пробует PDO, а при отказе —
консольный клиент `mysql` (на многих дистрибутивах root ходит через `unix_socket`,
который PDO не умеет).

Полный список ключей: `php bin/install.php --help`.

## Первый аудит

Веб-форма защищена Яндекс SmartCaptcha, и без ключей она заявку не примет. Для проверки
работоспособности капча не нужна — есть запуск из консоли:

```bash
php bin/audit.php https://example.com you@example.com --pages=5
```

Скрипт печатает оценку, разбивку проблем по разделам, путь к PDF и ссылку на отчёт.
`--pages=5` ограничивает обход: полный аудит 500 страниц занимает минуты.

Посмотреть отчёт в браузере:

```bash
php -S localhost:8000 -t public
```

Отчёт открывается по адресу `http://localhost:8000/api/report.php?id=<UUID из вывода>`.

## Что настроить дополнительно

| Переменная в `.env` | Зачем | Что будет без неё |
|---|---|---|
| `CAPTCHA_SITEKEY` / `CAPTCHA_SECRET` | Яндекс SmartCaptcha для веб-формы | форма не примет заявку, работает только `bin/audit.php` |
| `PAGESPEED_API_KEY` | полевые Core Web Vitals (LCP/INP/CLS) | раздел «Скорость» без данных реальных пользователей |
| `MAIL_*` | отправка отчёта на почту | письма не уходят, отчёт доступен только по ссылке |
| `CRAWLER_CONCURRENCY` | сколько страниц качать одновременно | по умолчанию 8 |
| `APP_TIMEZONE` | должен совпадать с поясом сервера и MySQL | даты в отчётах разъедутся |

`.env` в git не попадает. **Никогда не коммить `.env`** и не подставлять реальные
секреты в `.env.example` — репозиторий публичный.

## Проверка перед сдачей работы

```bash
composer test        # 133 модульных теста, сети и БД не требуют
php bin/check_env.php
```

Замер скорости обхода:

```bash
php bin/benchmark_crawl.php https://example.com --pages=20 --runs=3 --levels=1,4,8
```

## Диагностика типовых проблем

| Симптом | Причина и решение |
|---|---|
| `Class "SeoAuditor\..." not found` | Автолоадер оптимизирован и не знает о новом классе: `composer dump-autoload -o` |
| `Access denied for user` при установке | Неверные доступы к базе. Если базы ещё нет — передай `--db-root-user`/`--db-root-pass` |
| `Table 'seo_auditor.audits' doesn't exist` | Схема не применена: `php bin/install.php` или `mysql ... < sql/schema.sql` |
| `Unknown column 'host'` | База от старой версии. Установщик доберёт колонки сам, либо накати `sql/migration_001_comparison.sql` |
| `Не удалось загрузить ни одной страницы` | Сайт недоступен, блокирует бота по User-Agent или закрыт в `robots.txt`. Проверь `curl -I <url>` |
| PDF не создаётся | Нет расширения `gd` (нужно mPDF) или нет прав на запись в `REPORTS_DIR` |
| Форма отвечает «Проверка капчи не пройдена» | Нет или неверны ключи SmartCaptcha — для тестов используй `bin/audit.php` |
| HTTP 429 при отправке формы | Сработал лимит: 5 аудитов в час на IP. Для отладки очисти `logs/ratelimit/` |
| `Адрес недоступен для аудита` | `UrlGuard` не пускает на внутренние адреса и нестандартные порты — это защита от SSRF, а не ошибка |
| Кракозябры вместо кириллицы | База создана не в `utf8mb4` — пересоздай с нужной кодировкой |
| Даты в отчёте на несколько часов назад | `APP_TIMEZONE` не совпадает с поясом сервера и MySQL |
| Воркер не стартует на Windows | `exec("php ... &")` работает только на Unix. Локально запускай `php bin/audit.php` или `php jobs/worker.php` вручную |
| Раздел отчёта пуст, хотя проверка есть | Проверка упала, `AuditManager` глушит исключения в `error_log` — смотри `logs/worker.log` |
| `Undefined variable $что-то»` | В двойных кавычках нужно `«{$var}»`, а не `«$var»` — ёлочка прилипает к имени переменной. Ловится тестом `CodeStyleTest` |

Если проблемы нет в таблице: сначала `logs/worker.log`, затем воспроизведение через
`php bin/audit.php <url> --pages=3` и чтение стектрейса.

## Боевое развёртывание на VPS

Для чистого сервера (AlmaLinux 9 или другой RHEL-совместимый) есть скрипт, который
ставит виртуальный хост, SSL и базу:

```bash
DOMAIN=seo.example.ru ADMIN_EMAIL=admin@example.ru \
  ssh user@server 'bash -s' < setup_server.sh
```

Он выведет сгенерированный пароль базы — сохрани его в `.env`.

Дальше на сервере: `composer install --no-dev`, `php bin/install.php`, веб-рут направить
на `public/`. Воркер очереди запускается по cron раз в минуту (скрипт это настраивает).

Обновление кода на уже развёрнутом сервере:

```bash
DEPLOY_SERVER=user@example.com DEPLOY_REMOTE=/var/www/seo-auditor ./deploy.sh
```

Скрипт шлёт только изменённые в git файлы и пересобирает автолоадер Composer.

Что помнить про боевой сервер:

- Веб-рут — `public/`; каталог `api/` там лежит внутри `public/api/`
- `.env` на сервере свой, деплоем не перезаписывается — новые переменные добавляй руками
- После добавления **новых классов** обязателен `composer dump-autoload -o`
- Файлы должны принадлежать пользователю веб-сервера, `.env` — права `640`
- После деплоя: `php bin/check_env.php` и открыть любой существующий отчёт

## Как устроен проект

Полное описание архитектуры, схема БД, формулы оценки и результаты замеров — в `README.md`.
Кратко, что где лежит:

- `src/Core` — `Env`/`Config` (конфигурация), `Database` (PDO-обёртка), `Crawler`
  (параллельный обход), `UrlGuard` (защита от SSRF), `UrlTools`, `RateLimiter`, `RobotsTxt`
- `src/Checks` — 14 проверок, все наследуют `BaseCheck`
- `src/Audit/AuditManager` — оркестратор: краулинг → проверки → сравнение → отчёт → email
- `src/Report` — `ReportBuilder`, `Priority` (приоритеты P1–P4), `Score` (формулы оценки)
- `templates` — HTML-отчёт (светлая и тёмная тема) и PDF через mPDF
- `bin` — установщик, диагностика, аудит из консоли, пересборка PDF, замер скорости
- `api` + `jobs/worker.php` — эндпоинты и фоновая очередь

### Как добавить новую проверку

1. Создай класс в `src/Checks/`, унаследуй `BaseCheck`, реализуй контракт:
   ```php
   public function run(array $pages, array &$siteData): array
   ```
   Внутри вызывай `$this->critical(...)`, `$this->warning(...)`, `$this->info(...)`.
   Первый аргумент — `check_type`, он же ключ группировки в отчёте.
2. Зарегистрируй в массиве `$checks` в `AuditManager::run()`.
3. Добавь `check_type` в `$checkLabels` и нужную вкладку `$tabChecks` в `templates/report.php`,
   а также в `$checkLabels` в `templates/report_pdf.php` и `ReportBuilder`.
4. Проверь трудозатраты в `Priority::EFFORT_BY_TYPE` — иначе для типа возьмётся значение 2.
5. Прогони `php bin/audit.php <url> --pages=3` и посмотри результат в отчёте.

Чистую логику (разбор файла, вычисление) выноси в класс `src/Core/` и покрывай тестом,
как сделано с `RobotsTxt`. Проверки, которые ходят в сеть, тестами не покрываем.

## Работа с git

Ветки от `main`, осмысленные имена:

```bash
git checkout -b feature/wcag-check
git checkout -b fix/pdf-encoding
```

Перед коммитом убедись, что не тащишь лишнего, и прогони проверки:

```bash
git status --short
git diff --name-only --cached | grep '\.php$' | xargs -r -n1 php -l && composer test
```

## Чего не делать

- Не коммить `.env`, дампы базы, PDF-отчёты и скриншоты
- Не хардкодить секреты, адреса серверов и пути установки — репозиторий публичный,
  всё через `.env` и переменные окружения
- Не менять схему базы без миграции в `sql/`
- Не отключать `UrlGuard` в краулере: без него приложение по запросу пользователя
  сканирует внутреннюю сеть сервера
- Не ослаблять проверку капчи ради локального теста — для этого есть `bin/audit.php`
- Не хранить IP-адреса в открытом виде: это персональные данные по ФЗ-152
  (в `RateLimiter` они хешируются)
