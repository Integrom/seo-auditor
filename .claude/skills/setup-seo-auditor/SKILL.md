# Развёртывание «SEO Аудитора»

Помоги коллеге поднять проект и убедиться, что он работает. Основной принцип:
**не угадывай состояние окружения — запусти диагностику и действуй по её выводу.**

## Порядок работы

### Шаг 1. Клонирование и зависимости

```bash
git clone <repository-url> seo-auditor
cd seo-auditor
composer install
```

Требуется PHP ≥ 8.1 с расширениями `pdo_mysql`, `curl`, `mbstring`, `dom`, `json`, `gd`
и MySQL/MariaDB. Проверять руками не нужно — это сделает диагностика на шаге 4.

### Шаг 2. Конфигурация

```bash
cp .env.example .env
```

Заполни в `.env` минимум для локального запуска: `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASS`.

Остальное опционально:

| Переменная | Зачем | Без неё |
|---|---|---|
| `CAPTCHA_SITEKEY` / `CAPTCHA_SECRET` | Яндекс SmartCaptcha для веб-формы | форма не примет заявку — тестируй через `bin/audit.php` |
| `PAGESPEED_API_KEY` | полевые Core Web Vitals (LCP/INP/CLS) | раздел «Скорость» без данных реальных пользователей |
| `REPORTS_DIR` | куда складывать PDF | по умолчанию `reports/` в корне проекта |

`.env` в git не попадает — он в `.gitignore`. **Никогда не коммить `.env`** и не подставляй
реальные секреты в `.env.example`.

### Шаг 3. База данных

```bash
mysql -u root -p -e "CREATE DATABASE seo_auditor CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci"
mysql -u root -p seo_auditor < sql/schema.sql
mysql -u root -p seo_auditor < sql/migration_001_comparison.sql
```

Миграция обязательна: без неё нет колонок `host`, `previous_audit_id`, `score`,
`issue_key` — сравнение аудитов и оценка не работают.

### Шаг 4. Диагностика окружения

```bash
php bin/check_env.php
```

Скрипт проверяет 20+ пунктов: версию PHP и расширения, библиотеки Composer, автолоадер,
наличие `.env` и ключей, права на каталоги, подключение к БД, полноту схемы и миграции,
доступ в интернет. Возвращает код 1 при блокирующих ошибках.

Разбирай вывод построчно: `[FAIL]` — блокирует запуск, `[WARN]` — можно работать дальше.

### Шаг 5. Тестовый аудит

Запусти из консоли, минуя веб-форму и капчу:

```bash
php bin/audit.php https://example.com test@example.com --pages=5
```

`--pages=5` ограничивает обход — для проверки работоспособности достаточно, полный
аудит 500 страниц занимает минуты. Скрипт печатает оценку, разбивку проблем по разделам,
путь к PDF и ссылку на отчёт.

### Шаг 6. Просмотр отчёта в браузере

```bash
php -S localhost:8000 -t public
```

Отчёт: `http://localhost:8000/api/report.php?id=<UUID из шага 5>`
Главная с формой: `http://localhost:8000/` (нужны ключи капчи).

## Диагностика типовых проблем

| Симптом | Причина и решение |
|---|---|
| `Class "SeoAuditor\..." not found` | Автолоадер оптимизирован и не знает о новом классе: `composer dump-autoload -o` |
| `SQLSTATE[HY000] [1045] Access denied` | Неверные `DB_USER`/`DB_PASS` в `.env`; проверь `php bin/check_env.php` |
| `Table 'seo_auditor.audits' doesn't exist` | Не применена схема — шаг 3 |
| `Unknown column 'host' in 'where clause'` | Не применена `migration_001_comparison.sql` |
| Аудит падает с `Не удалось загрузить ни одной страницы` | Сайт недоступен, блокирует бота по User-Agent или закрыт `robots.txt`; проверь `curl -I <url>` |
| PDF не создаётся, в отчёте пусто | Нет расширения `gd` (нужно mPDF) или нет прав на запись в `REPORTS_DIR` |
| Веб-форма отвечает «Проверка капчи не пройдена» | Нет/неверные ключи SmartCaptcha — для тестов используй `bin/audit.php` |
| Кракозябры вместо кириллицы | БД создана не в `utf8mb4` — пересоздай с нужной кодировкой |
| Воркер не стартует на Windows | `exec("php ... &")` работает только на Unix; локально запускай `php bin/audit.php` или `php jobs/worker.php` вручную |
| В отчёте раздел пустой, хотя проверка есть | Проверка упала — `AuditManager` глушит исключения в `error_log`; смотри `logs/worker.log` |

Если проблема не в таблице — сначала посмотри `logs/worker.log`, затем воспроизведи
через `php bin/audit.php <url> --pages=3` и читай стектрейс.

## Как устроен проект

Полное описание архитектуры, схема БД и формулы оценки — в `README.md`.
Кратко, что где лежит:

- `src/Core` — `Env`/`Config` (конфигурация из `.env`), `Database` (PDO-обёртка), `Crawler` (обход сайта)
- `src/Checks` — 14 проверок, все наследуют `BaseCheck`
- `src/Audit/AuditManager` — оркестратор: краулинг → проверки → сравнение → отчёт → email
- `src/Report` — `ReportBuilder` (сборка) и `Priority` (приоритеты P1–P4, оценка часов)
- `templates` — `report.php` (HTML, светлая/тёмная тема) и `report_pdf.php` (PDF)
- `api` — эндпоинты; на сервере лежат в веб-руте `public/api/`
- `jobs/worker.php` — фоновая очередь с lock-файлом

### Как добавить новую проверку

1. Создай класс в `src/Checks/`, унаследуй `BaseCheck`, реализуй контракт:
   ```php
   public function run(array $pages, array &$siteData): array
   ```
   Внутри вызывай `$this->critical(...)`, `$this->warning(...)`, `$this->info(...)`.
   Первый аргумент — `check_type`, он же ключ группировки в отчёте.
2. Зарегистрируй в массиве `$checks` в `AuditManager::run()`.
3. Добавь `check_type` в `$checkLabels` и в нужную вкладку `$tabChecks` в `templates/report.php`,
   а также в `$checkLabels` в `templates/report_pdf.php` и `ReportBuilder`.
4. Проверь трудозатраты в `Priority::EFFORT_BY_TYPE` — иначе для типа возьмётся значение 2.
5. Прогоняй `php bin/audit.php <url> --pages=3` и смотри результат в отчёте.

## Рабочий процесс с git

Ветки от `main`, осмысленные имена:

```bash
git checkout -b feature/wcag-check      # новая функциональность
git checkout -b fix/pdf-encoding        # исправление
```

Коммиты на русском, императивом, тело — зачем менялось, а не только что:

```bash
git add -A
git commit
```

Перед коммитом проверь, что не тащишь лишнего — `.gitignore` исключает `.env`, `vendor/`,
`reports/`, `logs/`, скриншоты:

```bash
git status --short
git diff --cached --stat
```

Проверка синтаксиса всех изменённых PHP-файлов перед пушем:

```bash
git diff --name-only --cached | grep '\.php$' | xargs -r -n1 php -l
```

## Деплой на сервер

```bash
./deploy.sh
```

Скрипт копирует файлы по SSH и пересобирает автолоадер Composer.

Что помнить про боевой сервер:

- Веб-рут — `public/`; каталог `api/` на сервере лежит в `public/api/`, а не в корне проекта
- `.env` на сервере свой, деплоем не перезаписывается — новые переменные добавляй туда руками
- После добавления **новых классов** обязателен `composer dump-autoload -o` (в `deploy.sh` уже есть)
- Файлы должны принадлежать `nginx:nginx`, `.env` — права `640`
- Проверка после деплоя: `php bin/check_env.php` на сервере и открыть любой существующий отчёт

## Чего не делать

- Не коммить `.env`, дампы БД, PDF-отчёты и скриншоты
- Не хардкодить секреты в коде — только через `Env::get()` / `Config::get()`
- Не менять схему БД без миграции в `sql/` (продовая база обновляется только миграциями)
- Не удалять и не перезаписывать `.env` на сервере
- Не ослаблять проверку капчи в `api/start.php` ради локального теста — для этого есть `bin/audit.php`
